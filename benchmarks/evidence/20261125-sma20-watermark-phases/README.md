# 10M 行、单 Tokio 工作者的 SMA20 历史回退诊断

Python 公开作业从 2026.11.14 到定时任务的 main 源码树再次出现回退。在本机，p50 从 **329.407 ms 增至 518.327 ms**，p95 从 356.822 ms 增至 562.395 ms。两轮各十对的配对变化中位数为 **+57.34%**（区间 +44.33% 至 +59.83%）和 **+58.74%**（+50.81% 至 +70.79%），均满足维护的 +5% 回退判据。独立 CI 的 p50 为 408.74 → 560.29 ms。两处主机、亲和性与制品独立，两组毫秒数各自对照。

发布版提交为 `7012b5b4`，定时任务主线为 `72072c1d`。本机候选 wheel 实际由 `89cc36a8` 构建，其完整 Git 树 `cec8e19a`、产品源码摘要和 Cargo.lock 与定时主线相同。两端为各自干净版本的 release/locked、abi3 生产构建，CPython 3.13.9、Rust 1.94.0，采用同一组锁定依赖。端点对应已安装 site 与 wheel 文件逐份校验，通过 hello 复核运行进程加载的 native 哈希。协议在首个样本前锁定，未另行构建或补样。

差额集中在水位回调。每次作业，两版在 10 次 Data 回调接纳全部 1,000 万行，在 10 次 Watermark 回调完成全部实体解析、数值更新与结果准备，每版记 10 次串行、0 次通用及并行内核，随后 1 次 End 不再更新数据。两版共触及 640 个实体批次（64 个键 × 10 批），记录的既有实体状态拷贝由 576 次减至 0 次。44 次自然终止、边排空、输入和 sink 交付行数通过。标准 NumPy 分实体卷积与所有输出对照，9,998,784 个有限值和 1,216 个暖启动缺值位置匹配，最大绝对误差 8.53 × 10⁻¹⁴。验证按 sequence 排序并允许 Null 转 NumPy NaN，原始输出的物理顺序不属于该 oracle。

主线 slab 的 `route_slab` 为一千万行登记了 `ResolvedRows`，未开启 `RollingStage::EntityResolution`。因而候选在该阶段为零，同时 Other 增加，两者存在阶段分类变化。`fill_slab_rows` 的 NumericUpdate 区间包含 full-tick 检查、数值更新、结果追加及回退遍历，两个串行分支计入同一调用数。若要区分这几项，应对 `route_slab`、`prepare_slab_entities`、full-tick 准入检查与 ring 更新各自计时并核对正常产品时钟。各阶段每次样本之和恰等于所属 callback 时长；表中的配对中位数不能相加分摊总壁钟。这里测到的是 Python 公开作业内的 Rust 回调，独立原生 Rust 入口仍需单独计量。

每次只在原公开 ready-to-Arrow 时钟停止后读取两份状态，一份在 EOF 前，一份在通过 oracle、自然终止后。EOF 前没有活动或已完成的 checkpoint，managed journal 在启用状态。资源守卫 123 条记录均适合计量，核心 4 及其 SMT 同胞受到监控，可用内存最低 15,825,514,496 字节。用例十个百万行批次的输入、两轮预热及统计约定详见 `protocol.md` 与 `protocol.json`。

## 复算
