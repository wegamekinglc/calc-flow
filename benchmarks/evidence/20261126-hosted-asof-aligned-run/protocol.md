# Hosted ordered ASOF matching at ten million rows

Use four independent GitHub-hosted Ubuntu VMs, one for each comparison. Compare PR 753 e3104f444688ab3890c4b45f6098c28e052de7a8 separately with 11.14 7012b5b409553df04e29e6d7f9a11abf919cbf93 and its pre-change main f069199b25cd7893879df799a2d44e95d6a9cbad, on the native Rust StreamingRunner and the installed Python wheel. The WSL2 registration stopped before any completed observation when an external process saturated an SMT sibling. Retain that independent outcome.

Build all six frozen products on separate build VMs with identical release settings per surface. Reuse the same artifact for both candidate pairings. Record source, lock, fixture, toolchain and product hashes, and compare only the two paired products on the same measurement VM. Validate all ten million output rows in physical order, their prices, full post-EOF counts, state zero and absence of late or duplicate inputs. Time first ready through Batch formation for native and fully materialized Arrow table for Python. Use two independent rounds, each with one excluded warmup per arm and ten alternating pairs. Replay the official paired intervals; a regression requires both lower limits above +5%. Preserve partial results and stop reasons.

Four Tokio workers, 64 keys, ten one-million-row batches per input. Reserve one logical CPU per separate physical core, up to four, requiring at least two. On 4-vCPU/2-core hosts this gives four Tokio workers on two available physical cores, with both SMT siblings monitored separately. Record the original and selected topology. Do not pool across VMs or extrapolate to four physical cores. Before timing require selected and sibling utilization <=20%, host utilization <50%, >=10 GiB available, <256 major faults, <1024 swapped pages per interval. During timing require <50% on every excluded SMT sibling, <50% external host utilization and the same memory/paging thresholds. Compute external activity as total utilization less the measured process tree's exclusive cgroup CPU time, including exited workers. Record both raw and adjusted metrics. Change no process outside the benchmark's own process tree.

Allow 600 seconds for one measurement VM including fixture/installation, preflight, warmups, both rounds, oracle checks and replay (540 seconds for collection). Distinct build VMs have a separate 120-minute cold budget. Run once on a fresh VM and retain its original outcome. An incomplete group gets no performance verdict.
