# 千万行 ASOF 匹配的 Rust 与 Python 性能

PR #753 的生产提交为 `e3104f444688ab3890c4b45f6098c28e052de7a8`。左、右输入各一千万行，各分十批，按 64 个键进行有序 ASOF 匹配。每组独立比较同机的两个产品，每轮先各预热一次，再做十个交替配对，共两轮。下表时长的单位为毫秒。

| Python | 11.14           |  685.931 |  969.864 | +41.39%  |  717.435 | 1056.163 | 确认回退               |
| Rust   | 改动前 f069199b |  896.662 |  815.669 | −9.03%   |  962.552 |  874.039 | 未确认回退             |

相对 11.14，Python 两轮配对变化的置信下界分别为 +37.06%、+28.96%，均超过 +5% 的回退线。Rust 的两轮下界为 +2.65%、+3.42%，上界为 +10.66%、+14.32%。相对改动前，两端的两轮配对中位数均减少。Rust 两轮区间上界为 −0.26%、−2.51%，Python 为 −1.78%、−2.82%，尚未同时跨过正式改善线 −5%。所有区间的覆盖率为 97.85%。

Rust 计时从两个来源就绪至输出 Batch 装配，Python 计时至安装包交付完整 Arrow 表。时钟停止后提交 EOF，检查左右两侧各接纳一千万行、全部匹配及淘汰、状态清空。四组共 176 次执行均完成逐行物理顺序和数值校验。每组使用四个 Tokio worker，固定在两个物理核，每个物理核选一个逻辑 CPU，另外两条 SMT 线程用于监测竞争。每组使用独立 Ubuntu VM。Rust 的发布版对照使用 Intel Xeon Platinum 8370C，Python 的发布版对照使用 Intel Xeon 6975P-C，两组改动前对照均使用 AMD EPYC 9V45。绝对时长和百分比仅在各自行内解释。

先前的本地 WSL2 方案固定四个物理核。三个原生产品通过完整结果资格检查。正式预检后，CPU 2 的 SMT 同胞 CPU 3 占用达到 90%，超过取样上限 50%，第一组在获得首个观测前停止。该次运行无配对结论。[本地原始记录](asof-10m-wsl-stop.tar.gz)
