# ASOF UInt64 序列接纳的千万行实测

相对 11.14，Rust 的 p50 减少 116.21 ms（−12.94%），Python 的 p50 减少 108.82 ms（−17.97%）。两轮置信上界在两个入口均低于 −5%，符合正式改善判定。对直接父版本的两组均因外部 SMT 竞争提前结束，本次无法单独量化这一小阶段贡献的收益。

双侧各一千万行、64 个键、零容差、四个 Tokio worker。四组各使用独立的 GitHub 托管 VM，同组对照产品和候选共享机器。11.14 产品为 7012b5b409553df04e29e6d7f9a11abf919cbf93，直接父产品为 f67422bac9c0e23a8d22e717422c7b5bb329f723，候选产品为 40689a3318ea866e5e948e5ad2fdc2788cfa39b5。Rust 使用原生优化二进制，Python 使用独立环境安装的普通 wheel。

Rust 直接父组在 CPU 3 的利用率达到 51.0% 时停止，Python 直接父组在 CPU 1 达到 74.7% 时停止。正式区间的同胞占用上限为 50%。这两个区间中所有存活的测量 cgroup 线程均位于 CPU 0 和 2，内存、换页与整机外部 CPU 占用均在限制内。部分轮次只保留原始记录，两组均没有正式判定。
