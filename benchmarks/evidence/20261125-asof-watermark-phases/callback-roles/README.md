# ASOF 的右侧淘汰何时发生

对已归档的 Python 安装包原始记录重新分组。产品为 11.14 的 7012b5b4 与合入 #741 后的 ea7a21ce。负载每侧 100 万行、64 个键、四线程，独立构建的发布版与候选在同一轮配对。这里使用两轮各十对正式样本，每次作业有五次 finalize 回调。复算逐一检查请求、产品侧、轮次、样本序号、原始 trace 区间、按 sequence 校验的输出、末条回调的库存和阶段计时闭合。[原始报告及附件](../output-charge-followup)

右侧淘汰累计仅多用约 0.072 ms。实际有两项接近抵消的变化。产生结果的回调中，两侧都淘汰了全部 100 万条右侧载荷；在无联合水位的回调中，两侧淘汰的载荷数均为零。该候选的 20 次无联合水位回调中，13 次状态计费减少 16,000,000 字节，右淘汰均值为 3.347 ms；另外 7 次计费不变，均值为 0.140 ms。发布版的 20 次计费均不变，右淘汰均值为 0.0004 ms。最后一行将两个结束回调按作业累加，再对作业取平均。这里的字节数是整个回调前后算子账本的差。历史记录保留了末条回调状态及按 sequence 校验的输出，独立的作业终态与物理顺序校验从后续实验加入。冻结 trace 没有记录每个输入水位的到达顺序，无法按单侧水位给这些样本命名。[逐次观测](results.json)

产生结果的回调累计平均多用 21.112 ms，其中匹配及就绪判断多用 11.350 ms，Arrow 输出多用 10.332 ms。该回调以外的差距集中在上述无联合水位的一次调用。发布版本进入 finalize 前对既有淘汰任务的等待在这些墙钟之外。此组数据采集于整段输出计费、匹配游标及右侧完整淘汰等后续改动之前。[该版水位处理源码](https://github.com/wegamekinglc/calc-flow/blob/ea7a21cead99c424c1d4a6ce5dcf46abfc449aab/crates/calc-flow/src/operator/asof/finalize.rs) · [11.14 淘汰与等待](https://github.com/wegamekinglc/calc-flow/blob/7012b5b409553df04e29e6d7f9a11abf919cbf93/crates/calc-flow/src/operator/asof/finalize.rs)
