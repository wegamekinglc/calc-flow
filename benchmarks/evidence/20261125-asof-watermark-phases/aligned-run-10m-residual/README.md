# 千万行 ASOF 作业内的左侧接纳成本

在相同的 ready→最后一份 Batch 或 Arrow 表交付区间内，11.14 与 PR #753 的主要差距均出现在左输入接纳。Rust 从 198.86 增至 328.31 ms，Python 安装包从 176.59 增至 354.05 ms。两轮配对的左接纳差额置信区间，Rust 为 [114.86,171.23]、[79.48,165.81] ms，Python 为 [142.97,219.38]、[159.77,226.68] ms。

每个入口的普通产品和插桩产品在同一台独立托管 VM 上分组运行。11.14 为 `7012b5b4`，候选为 `e3104f44`。每侧一千万行、64 键、四个 Tokio worker，固定到两个物理核各一条逻辑 CPU。普通 Rust 对照在 AMD EPYC 9V45 上的 p50 为 726.17→816.59 ms（+12.45%，确认回退），普通 Python 在 AMD EPYC 9V74 上为 792.25→874.09 ms（+10.33%，不确定）。之前单独的 Intel Python 对照已确认 +41.39% 回退。不同 VM 的绝对时长或百分比不宜相减。

下表为插桩组 20 次正式作业中，候选减去发布版的每作业平均累计毫秒。前五行使用同一个时窗。每作业十次左接纳、十次右接纳和二十次水位处理完整落在时窗内，后续三次水位回调完整落在时窗外。四组共 176 次预热或正式执行均校验全部行的值、物理顺序和结束状态。

候选左输入的索引安装耗费 Rust 104.15 ms、Python 133.66 ms，定位符验证分别耗费 54.33、64.03 ms。整批载荷复制分别为 65.63、51.13 ms，序列编码为 51.90、45.31 ms，选中列预算为 12.78、17.72 ms。发布版将部分同类工作归入较粗的 prepare 阶段，上述细项表示候选自身的成本。每个候选作业在两侧预算计费时实际访问一亿个列基数掩码元素、两千万个记录基数掩码元素、两千万个变长值长度。后续验收可分别追踪这部分预算和左索引安装。

Python 发布十个输入块的累计差额为 +0.01 ms，十次转为 PyArrow 的累计差额为 +0.02 ms，最终拼表两侧均约 0.04 ms。等待各块输出的差额为 +23.24 ms，其中包含异步引擎的工作。插桩组相对本机普通组的 p50 移动，Rust 发布版 +2.58%、候选 +2.37%，Python 发布版 +1.50%、候选 −3.74%。这些变化包含不同采样时段的波动。分段结果用于定位，普通产品仍是性能判定依据。
