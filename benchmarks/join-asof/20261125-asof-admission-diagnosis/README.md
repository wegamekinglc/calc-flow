# Managed ASOF admission and watermark diagnosis

The 11.14 release and candidate 6269bda3 had no qualified paired timing for this diagnosis. The three-second preflight passed. The first subsequent resource interval recorded 418 major faults against a limit of 256, 1 swap-in page and 2.55% host CPU utilization. The controller stopped after 7.038 seconds of the 120-second budget. Zero formal samples completed, and neither the relative cost of admission nor the relative cost of output delivery was established. [Outcome and resource intervals](result.json)

The release worker independently recorded an excluded warmup while the controller was cancelling it. Before either watermark, this observation contained one million accepted and pending left rows, one million accepted and retained right rows, and zero emitted or delivered rows. Its final output passed the full sorted sequence and value oracle with zero maximum absolute error. No candidate warmup or paired observations are available. The single discarded warmup is preserved in the original journal.

The registered schedule used the existing managed 4-thread ASOF EngineCase, one million rows per side, 64 symbols and zero tolerance. From a ready empty runner it pushed reference Data then quotes Data, observed operator acceptance on both sides, then pushed the same reference and quotes watermarks, awaited full delivery and concatenated the Arrow batches. Every status call and its timestamp, requested 1 ms polling sleeps, actual publication order, phase boundaries and queue-to-delivery row counts were included in the worker record. Polling was charged to the admission clock. The altered publication schedule makes these phase clocks diagnostic. The original scheduled comparison uses its own independently recorded throughput clock.

The protocol required two rounds of ten alternating pairs and four excluded warmups, reused the independently sealed release wheels, and checked all outputs and all four SMT groups against the same public-case resource limits. The archive contains the original telemetry, failed request, warmup, manifests, release hashes and registered diagnostic code. [Original evidence](raw-evidence.tar.gz) · [File hashes](receipt.json)
