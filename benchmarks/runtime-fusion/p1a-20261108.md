# P1a row-local runtime fusion: measurement protocol

Status: preregistered; no performance measurement has run.

This compares the P1a admission expansion with main `8d8be7d9`. Both
revisions execute the same maintained warm-stream harness. The target lowers to
exactly two native nodes: a 20-row Rolling mean followed by an Expression with
`symbol < 'S032'` and `mean * 2.0 + 1.0`. Python lowering retains the boundary. Admission still needs verification: the
lowered Expression omits an output-port schema, so implementation must establish
the required schema proof on this normal application path before acquisition.
The original mean-only workload is the control for the already-admitted
projection path. The arithmetic/filter indicator rejects sparse appends;
existing complete-tick validation also rejects append sizes not divisible by
the entity count, so each supported append retains rows.

## Fixed case selection

| Case                             | History rows | Append rows | Entities | Window | Retained output rows per append | Forced GC |
|----------------------------------|--------------|-------------|----------|--------|---------------------------------|-----------|
| `rolling_mean_arithmetic_filter` | 10,240       | 64          | 64       | 20     | 32                              | false     |
| `rolling_mean`                   | 10,240       | 64          | 64       | 20     | 64                              | false     |

The invocation uses `--exact-matrix --history-rows 10240 --append-rows 64`
with only these two indicators and `--gc-modes normal`. The expanded matrix was
verified to contain exactly these two cases and no 1,024,000-row history point.

Each case uses a fresh isolated baseline/candidate worker pair, the same
candidate harness, four Tokio workers, the ordinary allocator and unchanged
checkpoint settings. Both workers warm their own real StreamingRunner before
sampling. There are exactly 30 alternating AB/BA append pairs per case. These
are persistent-state append samples, not 30 fresh process pairs.

The maintained `profile_warm_stream.py` contract is used directly, including
its fixed-seed 20,000-resample bootstrap of paired speedup medians, native and
wheel seals, source and toolchain checks, worker environment equality, strict
per-append oracle validation, callback intervals and terminal resource/status
observations. This is the standalone `paired-warm-stream-v1` contract, not the
release gate's two-round fresh-process verdict.

## Timing, budget and decision

The timer starts with prepared Data enqueue and ends after sink delivery and
conversion to Arrow. Source/task/channel work, rolling, watermark finalization,
projection and output conversion remain timed. Compilation, startup, history
construction, validation, IPC, checkpointing and shutdown are outside each
sample, but inside the total acquisition budget.

The two cases together have a 600-second wall-clock limit, including setup,
preflight, fixture/history work, warmup, correctness, startup and cleanup.
Expected acquisition time is below 180 seconds. No extra scale, GC mode,
thread count, case, repetition or favorable retry is included.

The target establishes a material speedup only if its paired median speedup
exceeds 1.05 and the maintained bootstrap 95% interval has a lower bound above
1.0. Report the control's full interval and timings, without interpreting an
interval containing 1.0 as proof of equivalence. A control interval wholly below
`1 / 1.05` is evidence of a material regression and prevents acceptance.
Insufficient precision, incompatible identity, incorrect output, budget
exhaustion or an unsuitable environment cannot support a merge.

The host is WSL2. Before acquisition, record current load, available memory,
affinity, native hashes and exact harness hashes. Wait for owned compilation
and tests to finish. Stop rather than classify timings if the environment is
unsuitable. Settle all owned worker processes on completion or failure.

## Correctness preparation

The new arithmetic/filter indicator first failed both focused tests with
`unsupported warm indicator`, then passed after its implementation. The tests
validate retained row identity, transformed mean values, rejection of missing
rows and incorrect values, and continued state advancement across two appends.
The directly affected warm-stream module passed 52 tests; the maintained
profile script passed 26 tests. Subsequent red/green guards reject unsupported
sparse filter shapes and keep exact matrix selection to two cases (the old
selector failed with four). The affected profile script then passed 27 tests. These checks used the sealed baseline native
module, demonstrating that the shared harness works on the old runtime too.
No performance conclusion follows from these correctness runs.
