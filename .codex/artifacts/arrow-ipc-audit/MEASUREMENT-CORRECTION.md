# 正式统计前的计时边界修正

首次 40 次采集及逐值核对完成后，最终边界审计发现 streaming worker 在父进程
round-trip 时钟内、core 时钟之前调用完整 oracle，仅为获得 expected_rows。
这增加了测试适配的 NumPy/Arrow 构造工作，违反预记的 fixture 在往返计时外的边界。
核心时钟不含该工作，但不能把首次往返数字当成符合契约的 IPC 路径。

原始 40 次的 Arrow 输入/输出、时钟、校验和及全部八份精确 Python 源码保留在原始包
`first-pass/`，`exclusion.json` 明确不纳入最终统计，不覆盖或混合样本。
修正仅将 worker 的输出数量预算改为固定 fixture 的标量公式，完整 oracle 仍在父进程
结果消费后的校验阶段。产品代码、结果算法、输入及资源配置不变。

随后仍按原四个场景、每 arm 五次、相同 ABC/CBA 顺序采集一次 40 次替代数据。
此处是修复计时契约偏离，不是为减小 spread 或获得有利结果追加样本；不再增加重复。
两轮采集、预检、接口和边界 probe 均计入原 600 秒测量总预算，构建时间另计。
