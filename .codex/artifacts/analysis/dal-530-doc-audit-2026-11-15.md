## 发现与修订

1. `docs/api-reference.md` 把 capability schema 写为 4；当前常量和类型是 5。
   改为 5，并说明 operator 和 provider 都有 `state_layouts`。
2. 概览仍把 `engine=` 写成 Program 唯一必需入口。对照构造重载和选择校验，
   在根 README、AGENTS、introduction、API reference 和 symbolic API 中统一
   `mode="batch"|"stream"`，保留 legacy engine 的互斥别名契约，说明没有默认值，
   以及 `for_mode` 创建独立声明 wrapper。
3. 数组指南把独立 ArrayExpr 一概描述为仅声明。对照 `ArrayExpr.collect_array`
   与现有 Python API，补齐 native 阻塞批量收集入口、显式 Runtime 注册、
   NativeArray 返回值，保留 Program 表收集和便捷流不支持独立数组输出的边界。
4. query-history、relational-frontends 和 DISTINCT 文档混用 analysis revision
   4、5、9；当前 Rust producer、Python decoder 和严格执行门禁均为 schema 2 /
   revision 11。统一当前值，保留受支持旧报告可读与当前执行授权的区别。
5. 根 README、API reference、Python API、symbolic API、workflows 和 design
   仍把 append stream SQL 限为单 alias。同步当前精确 schema 的 UNION ALL 子集，
   链接其 admission 限制，未扩展为任意多 alias SQL 支持。
6. 将已存在的 bounded analytic OVER guide 加入文档索引。
   对齐触及的表格；不改历史数据和数值结论。

这是现有行为的文档修正，没有产品/API/检查点格式变化，不新增 CHANGELOG。
AGENTS 中的 Program 说明已同步；CLAUDE 只委托 AGENTS，未重复该签名或命令，
