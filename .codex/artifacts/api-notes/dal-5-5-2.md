# DAL-5 5.2 Execution Options Contract — API Note

Status: public API frozen by `cf-api-designer` and approved by `cf-critic`
after the blocking amendments recorded below; implementation has not started.

Baseline:
`86ffb574d49e39fa275dd0ec39192a053283a234`
(PR #28 squash merge).

Upstream specification:
`.codex/artifacts/specs/dal-5-5-2.md`.

This note resolves the API decisions left open by the upstream specification.
If a candidate signature or transport detail in that specification conflicts
with this note, this note is authoritative for implementation.

## 1. Decision Summary

DAL-5 5.2 is an additive Python execution-context feature:

- add a pure-Python, immutable `calc_flow.ExecutionOptions` value;
- add keyword-only `options` to Python `ExecutionPlan.execute()` and
  `execute_async()`;
- add keyword-only `accepts_execution_options` to the public single-array
  `Runtime.register_provider()` registration path;
- preserve the existing two-argument callback by default and call a
  three-argument callback only after explicit opt-in;
- add the public Rust accessor
  `RunContext::deadline() -> Option<&DateTime<Utc>>`;
- use canonical strict-JSON text plus a canonical UTC microsecond timestamp as
  the private Python/PyO3 transport;
- carry the callback opt-in only in the trusted parent-to-worker registration
  projection.

The following do not change:

- Rust `ExecutionOptions` fields;
- project format v2 or its generated schema;
- checkpoint data;
- 5.1 capability schema version 1 or any capability response field;
- `/api/v2/catalog`, `/api/v2/capabilities`, validation, run, or result REST
  contracts;
- `web-ui/openapi.json` or generated TypeScript;
- mapped providers, NumPy/JAX helpers, scalar UDFs, sources, sinks, and runners;
- Studio preview limits or the worker call `plan.execute(batches)`.

The critic found three blocking ambiguities in the pre-review text: Python
surrogate code points were not portable through Rust `String`, callback-error
versus deadline precedence conflicted with the existing core order, and the
specification's abbreviated worker rule could be read as permitting mapped
providers to opt in. The amended specification and this note resolve all
three. The complete clarifications are:

1. `execute_async()` remains a regular method returning `Awaitable`, as it is
   today, so validation and defensive input copying continue to happen when
   the method is called.
2. The provider opt-in is available only on public single-array
   `register_provider()`. A `True` value attached to a private mapped
   registration is a malformed worker projection and fails closed.
3. The Python/PyO3 deadline transport is now fixed as canonical RFC 3339 UTC
   text with exactly six fractional digits; it is not a float epoch.
4. Settings keys and string values reject every Unicode surrogate code point,
   paired or unpaired, so the Python snapshot has an exact Rust
   `serde_json::Value` round trip.
5. The existing post-operator order remains authoritative: cancellation or
   deadline expiry wins over an operator/provider error observed by the same
   post-operator check.
6. The worker rule is mode-sensitive: mapped registrations never acquire a
   three-argument callback through this flag.

## 2. Public Python Surface

### 2.1 Module and export

Add:

```text
python/calc_flow/execution.py
```

The class is defined in that module and re-exported from
`python/calc_flow/__init__.py`:

```python
from calc_flow import ExecutionOptions
from calc_flow.execution import ExecutionOptions
```

Both imports name the same class object. `ExecutionOptions` is present exactly
once in `calc_flow.__all__`.

`JSONValue` is a typing helper in `calc_flow.execution`; it is not added to
the top-level `calc_flow.__all__`.

### 2.2 Frozen value object

The public signature is:

```python
from collections.abc import Mapping
from datetime import datetime
from typing import final

type JSONValue = (
    None
    | bool
    | int
    | float
    | str
    | list["JSONValue"]
    | dict[str, "JSONValue"]
)


@final
class ExecutionOptions:
    def __init__(
        self,
        *,
        settings: Mapping[str, JSONValue] | None = None,
        deadline: datetime | None = None,
    ) -> None: ...

    @property
    def settings(self) -> dict[str, JSONValue]: ...

    @property
    def deadline(self) -> datetime | None: ...
```

The concrete implementation must be a frozen, slotted pure-Python value
container. It may use a frozen dataclass with a custom initializer, but it
must not be a native pyclass and must not store a native cancellation token.

Value semantics are:

- equality compares the canonical settings snapshot and normalized deadline;
- equal values have equal hashes;
- assignment and deletion of fields fail as for a frozen dataclass;
- there is no instance `__dict__`;
- the object never retains the caller's mapping, nested mappings, or lists;
- every `settings` property access returns a new exact `dict`/`list` tree;
- `deadline` is either `None` or an exact base `datetime` whose
  `tzinfo is UTC`;
- `repr()` and `str()` do not include settings keys, settings values, timezone
  names, or the deadline timestamp.

The exact representation is:

```text
ExecutionOptions(settings=<empty>, deadline=<unset>)
ExecutionOptions(settings=<redacted>, deadline=<unset>)
ExecutionOptions(settings=<empty>, deadline=<set>)
ExecutionOptions(settings=<redacted>, deadline=<set>)
```

`str(value)` equals `repr(value)`.

### 2.3 Examples

```python
from datetime import UTC, datetime, timedelta

from calc_flow import ExecutionOptions

options = ExecutionOptions(
    settings={
        "trace": {"enabled": True},
        "retry_budget": 2,
    },
    deadline=datetime.now(UTC) + timedelta(seconds=30),
)

assert options.deadline is not None
assert options.deadline.tzinfo is UTC

copy = options.settings
copy["retry_budget"] = 99
assert options.settings["retry_budget"] == 2
```

An aware non-UTC input preserves its absolute instant:

```python
from datetime import datetime, timedelta, timezone

from calc_flow import ExecutionOptions

local = datetime(
    2026,
    7,
    28,
    12,
    34,
    56,
    123456,
    tzinfo=timezone(timedelta(hours=8)),
)
options = ExecutionOptions(deadline=local)

assert options.deadline == datetime(
    2026,
    7,
    28,
    4,
    34,
    56,
    123456,
    tzinfo=timezone.utc,
)
```

## 3. Strict JSON Settings Contract

### 3.1 Accepted input

`settings=None` and omitted `settings` both produce an empty object.

The root accepts a `collections.abc.Mapping`. Nested JSON objects also accept
`Mapping`; JSON arrays accept only exact `list` values. Input mappings are
consumed only during construction and normalized to exact built-in
`dict`/`list` containers. Custom mapping behavior is never retained.

Accepted scalar leaves use exact built-in types:

- `None`;
- `type(value) is bool`;
- `type(value) is int`, in the inclusive portable serde JSON range
  `[-2**63, 2**64 - 1]`;
- `type(value) is float`, only when finite;
- `type(value) is str`, with no code point in the surrogate range
  `U+D800..U+DFFF`.

All object keys use exact `str` and obey the same no-surrogate rule. Subclasses
of the scalar types, `IntEnum`, `Decimal`, tuples, sets, bytes, datetime
values, modules, classes, callables, and path objects are not strict JSON data.

Python permits surrogate code points inside `str`, but Rust `String` does not.
`serde_json` rejects lone surrogates and normalizes an escaped surrogate pair
to one Unicode scalar. Accepting either form would therefore make a value
accepted by the public constructor fail or change during the native round
trip. Rejecting every surrogate code point is the closed, lossless contract;
ordinary non-ASCII Unicode scalar text remains accepted.

String values that happen to contain a path, URL, token, or password remain
ordinary JSON strings. Calc Flow assigns them no path, secret, callback, or
import semantics. They are captured in the private snapshot but never copied
into validation messages or object representations.

### 3.2 Depth, cycles, aliases, and canonicalization

The top-level settings object has depth zero. A child has its parent's depth
plus one. Depth 32 is accepted and depth 33 is rejected, matching
`calc_flow::MAX_JSON_DEPTH`.

The copier tracks only ancestors on the current traversal path:

- a true cycle is rejected;
- a shared acyclic child is accepted and independently copied at each
  occurrence;
- mutation of any original alias after construction cannot affect the stored
  value.

The implementation must:

1. check the root before invoking native code;
2. snapshot mapping items once;
3. reject non-string, surrogate-containing, and duplicate object keys before
   descending;
4. sort object keys for deterministic traversal and canonicalization;
5. validate and copy every value to exact built-in containers/scalars,
   rejecting surrogate-containing string values;
6. encode with `json.dumps(..., allow_nan=False, sort_keys=True,
   separators=(",", ":"))`;
7. store only that canonical string;
8. decode a fresh tree for every public `settings` read.

Exceptions raised by a custom `Mapping` while it is copied are replaced with a
stable, redacted `ValueError` using `raise ... from None`.

### 3.3 Redacted structural locations

Errors identify the correct API label and structural shape without echoing
object keys or values.

The path language is:

- `$` for the root;
- `.*` for any object value;
- `[N]` for an array element.

For example, an invalid value in the third item of a list stored in any root
object field is reported at `$.*[2]`. Object key names are deliberately
redacted. This is less specific than a JSONPath containing user keys, but it
prevents a dynamic secret used as a key from reaching an exception or log.

### 3.4 Stable Python errors

The following messages are public compatibility commitments:

| Condition                                      | Exception    | Exact message                                                                  |
| ---------------------------------------------- | ------------ | ------------------------------------------------------------------------------ |
| root is neither `Mapping` nor `None`            | `TypeError`  | `settings must be a mapping or None`                                           |
| callable mapping or nested unsupported value   | `ValueError` | `settings at <path> contains a non-JSON value`                                 |
| object key is not exact `str`                   | `ValueError` | `settings at <path> contains a non-string object key`                          |
| string key or value contains a surrogate code point | `ValueError` | `settings at <path> contains a non-portable Unicode string`                |
| mapping produces a duplicate key               | `ValueError` | `settings at <path> contains duplicate object keys`                            |
| integer is outside the portable range          | `ValueError` | `settings at <path> contains an integer outside the portable JSON range`       |
| float is NaN or infinite                       | `ValueError` | `settings at <path> contains a non-finite JSON number`                         |
| current container closes a cycle               | `ValueError` | `settings at <path> contains a cycle`                                          |
| child depth exceeds 32                         | `ValueError` | `settings exceeds the maximum JSON depth of 32 at <path>`                      |
| mapping iteration/copy fails                   | `ValueError` | `settings could not be copied as strict JSON data`                             |
| normalized canonical encoding unexpectedly fails | `ValueError` | `settings could not be encoded as strict JSON data`                         |

`<path>` is substituted only with tokens from the redacted path language
above. No message includes `repr(value)`, a user key, a type name derived from
a user class, or a chained raw exception.

5.2 intentionally sets no byte-count or item-count limit for settings. This is
a local, trusted Python API; project JSON and Studio requests cannot source the
value, and callers can already provide much larger input batches. Depth,
numeric portability, cycles, and exact Unicode scalar transport remain
bounded. Implementations must not introduce an extra log/repr copy, and a
future public size cap would require its own compatibility decision and stable
error rather than an undocumented native-only threshold.

### 3.5 Label-aware helper

The implementation should extract a private pure helper rather than reuse the
current project validator with its hard-coded `project` prefix:

```python
def _canonical_json_object(
    value: Mapping[str, object] | None,
    *,
    label: str,
) -> str: ...
```

The helper belongs in a private module such as `calc_flow._json`. It accepts a
label and implements the algorithm above.

Existing project/checkpoint/state errors are compatibility surfaces. Migrating
those call sites to the helper is allowed only when their current exception
types and messages remain covered; it is not required for 5.2. In particular,
5.2 must not accidentally report a settings error with the word `project`.

## 4. Deadline Contract

### 4.1 Accepted input and normalization

`deadline=None` and omitted `deadline` both mean no engine deadline.

Any `isinstance(value, datetime)` value is accepted as a candidate, then
normalized to an exact base `datetime`. The candidate must:

- return a non-`None` UTC offset;
- be convertible to the `UTC` singleton imported from `datetime`;
- produce a UTC instant inside Python's representable year range;
- preserve its exact microsecond.

The constructor calls `utcoffset()` and `astimezone(UTC)` inside a
redacting error boundary, then reconstructs an exact base `datetime` from the
normalized components. A datetime subclass or custom `tzinfo` object is never
retained.

Naive datetimes are never interpreted using the machine's local timezone.
Dates in the past are valid construction inputs; they fail as cancellation
only when execution reaches the engine's existing cancellation checkpoint.

### 4.2 Stable Python errors

| Condition                                          | Exception    | Exact message                                                              |
| -------------------------------------------------- | ------------ | -------------------------------------------------------------------------- |
| value is neither `datetime` nor `None`              | `TypeError`  | `deadline must be a datetime or None`                                      |
| `utcoffset()` is `None`                             | `ValueError` | `deadline must be timezone-aware`                                          |
| offset lookup, UTC conversion, or range check fails | `ValueError` | `deadline must be a valid timezone-aware datetime representable in UTC`    |

The input object's repr, timezone name, timestamp, offset, and raw exception
are not included in the error or chained traceback.

### 4.3 Exact private encoding

Across the Python/PyO3 boundary, a non-`None` deadline is encoded as:

```text
YYYY-MM-DDTHH:MM:SS.ffffffZ
```

Properties:

- Gregorian year has exactly four digits in Python's range 0001–9999;
- the timezone is always literal `Z`;
- the fractional component is always present with exactly six digits;
- no float epoch, local timezone, nanosecond rounding, or duration is used.

The Rust side parses this exact private format and obtains a
`chrono::DateTime<Utc>`. Any malformed direct `_native` call fails before the
plan lock or state lifecycle begins and uses the redacted private error:

```text
invalid execution deadline transport
```

## 5. Python `ExecutionPlan` Contract

The exact public signatures preserve the current regular-method shape:

```python
from collections.abc import Awaitable, Mapping

from calc_flow import Batch, ExecutionOptions, RunResult


class ExecutionPlan:
    def execute(
        self,
        inputs: Mapping[str, Batch],
        *,
        options: ExecutionOptions | None = None,
    ) -> RunResult: ...

    def execute_async(
        self,
        inputs: Mapping[str, Batch],
        *,
        options: ExecutionOptions | None = None,
    ) -> Awaitable[RunResult]: ...
```

`options` cannot be positional.

Only `None` or an exact `ExecutionOptions` instance is accepted. Subclasses
are rejected because the native payload must come from the frozen class, not
an overridden property or transport hook.

The exact public type error is:

```text
options must be an ExecutionOptions or None
```

### 5.1 Call-time behavior

For `execute()`:

1. preserve the existing running-event-loop check and its existing
   `RuntimeError` precedence;
2. defensively copy the inputs mapping as today;
3. validate `options`;
4. pass the normalized private payload to `_native.ExecutionPlan.execute`.

For `execute_async()`:

1. defensively copy the inputs mapping at method call time, as today;
2. validate `options` at method call time;
3. return an awaitable whose execution passes the captured inputs and options
   payload to the native async entry.

Omitted `options`, `options=None`, and `ExecutionOptions()` all produce:

```text
settings_json = "{}"
deadline_utc = None
```

Each native invocation creates a fresh Rust `CancellationToken`. Neither the
Python value nor a prior invocation owns or reuses the token.

### 5.2 Cancellation, deadline, and rollback

The existing execution lifecycle is authoritative:

- malformed private settings/deadline transport fails before the plan lock and
  cannot create a transaction marker;
- an absolute deadline is not extended while waiting for the plan run lock;
- after the lock, existing recovery, input validation, state snapshot, and
  rollback-marker creation happen before the first deadline check; an error in
  any of those earlier stages keeps its existing precedence even if the
  deadline is already expired;
- `RunContext` is created with the captured absolute deadline;
- the existing check immediately before the first operator prevents an
  already-expired execution from calling that operator;
- checks immediately before and after every operator remain unchanged;
- a deadline does not preempt a synchronous Python callback while that
  callback is running;
- expiration is observed at the next cooperative check;
- deadline expiry maps to the existing Python `CancelledError`;
- the existing rollback/recovery marker and asyncio future cancellation
  mechanism remain the only completion/rollback path;
- cancellation and deadline do not create a second task, second token, or
  background watcher.

If an operator returns an error and the deadline is also expired at the
post-operator check, existing core ordering remains authoritative:
`CancelledError` wins because `check_cancelled()` runs before the operator
result is unwrapped. 5.2 does not change that precedence.

Cancelling an async task while it is only waiting for the plan lock creates no
transaction marker. Cancelling it after the authenticated rollback marker was
created may leave that one marker for the existing recovery path; the next
plan operation recovers it exactly once. 5.2 must not add a competing watcher,
rollback task, or completion path.

## 6. Provider Registration and Callback Arity

### 6.1 Exact public registration signature

Only public single-array registration gains the opt-in:

```python
from typing import Any


class Runtime:
    def register_provider(
        self,
        provider: str,
        name: str,
        version: str,
        callback: Any,
        *,
        options_schema: ProviderOptionsSchema | None = None,
        accepts_execution_options: bool = False,
    ) -> None: ...
```

`accepts_execution_options` is the final parameter name. It is keyword-only,
defaults to `False`, and accepts only `type(value) is bool`.

The exact error is:

```text
accepts_execution_options must be bool
```

Validation order preserves the existing `options_schema` error when both
keyword arguments are invalid, then validates
`accepts_execution_options`. Both checks occur before the registration lock,
native registry mutation, Python-root retention, registration-record append,
or capability revision advance.

The private mapped registration signature does not gain this argument:

```python
def _register_mapping_provider(
    self,
    provider: str,
    name: str,
    version: str,
    callback: Any,
    *,
    input_ports: Sequence[tuple[str, str]],
    output_ports: Sequence[tuple[str, str]],
    options_schema: ProviderOptionsSchema | None = None,
) -> None: ...
```

### 6.2 Callback invocation

Legacy/default:

```python
def callback(batch: Batch, operator_options: dict[str, JSONValue]) -> Batch: ...
```

Explicit opt-in:

```python
def callback(
    batch: Batch,
    operator_options: dict[str, JSONValue],
    execution_options: ExecutionOptions,
) -> Batch: ...
```

Rules:

- `False` always means exactly two positional arguments.
- `True` always means exactly three positional arguments.
- No `inspect.signature()`, `__signature__`, code-object inspection, trial
  call, `TypeError` retry, decorator unwrapping, or `contextvars` negotiation
  is allowed.
- A callable with the wrong arity is called once and fails through the
  existing `ProviderError` mapping.
- The third argument is an exact `ExecutionOptions`, reconstructed from the
  actual operator's `RunContext`, not the original caller object.
- Every opted-in operator invocation receives a fresh value object. Values
  within the same execution compare equal.
- Reading and mutating `execution_options.settings` cannot affect the caller,
  another callback, a later operator, or a later execution.
- The deadline is the same normalized UTC instant and microsecond observed by
  Rust.
- Callback return conversion, array ownership, output validation, and
  exception categories do not change.
- Python provider callbacks remain synchronous callables. This feature does
  not introduce an async callback protocol.

The optional compile-time callback method keeps its current signature:

```python
callback.validate(operator_options)
```

It never receives execution options because validation occurs during compile,
outside a run context.

### 6.3 Registration and fingerprint semantics

The flag is runtime registration behavior:

- it is captured by the provider factory used by subsequently compiled plans;
- it does not enter `ExternalOperatorSpec.options`;
- it does not enter project JSON;
- it does not enter operator configuration or the pipeline fingerprint;
- it does not change provider identity `(provider, name, version)`;
- it does not enter capability schema v1.

This matches existing callback-implementation behavior: changing registered
Python code does not change a data-only project fingerprint.

A rejected flag or duplicate native registration does not append the Python
registration record and does not advance capability revision. NumPy/JAX
compound helper behavior is unchanged: their public expression registration
uses the default `False`, their mapped registration has no flag, and two
successful registrations still advance revision twice.

## 7. Rust Public Surface

Add one additive accessor:

```rust
use chrono::{DateTime, Utc};

impl RunContext {
    /// Returns the absolute UTC deadline for this run, if one was configured.
    ///
    /// The deadline is checked cooperatively at engine work boundaries.
    pub const fn deadline(&self) -> Option<&DateTime<Utc>> {
        self.deadline.as_ref()
    }
}
```

The borrowed type is frozen exactly as
`Option<&DateTime<Utc>>`, not an owned clone, epoch, duration, or
`SystemTime`.

`RunContext` remains publicly exported. `OperatorContext` already exposes
`pub run: &RunContext`; no duplicate `OperatorContext::deadline()` is added.

The existing accessor remains:

```rust
pub fn settings(&self) -> &JsonMap;
```

Rust `ExecutionOptions` remains:

```rust
pub struct ExecutionOptions {
    pub settings: JsonMap,
    pub deadline: Option<DateTime<Utc>>,
    pub cancellation: CancellationToken,
}
```

No serde implementation, new field, builder, constructor, or cancellation
accessor is approved by 5.2. The new accessor requires rustdoc and direct tests
for `None`, UTC microseconds, `for_node()` preservation, and no mutation.

## 8. Private Python/PyO3 Bridge

### 8.1 Native execution methods

The private stub becomes:

```python
class ExecutionPlan:
    def execute(
        self,
        inputs: dict[str, Batch],
        *,
        settings_json: str = "{}",
        deadline_utc: str | None = None,
    ) -> RunResult: ...

    def execute_async(
        self,
        inputs: dict[str, Batch],
        *,
        settings_json: str = "{}",
        deadline_utc: str | None = None,
    ) -> Awaitable[RunResult]: ...
```

Defaults preserve direct internal calls made by existing binding tests. These
keywords are private transport, not an alternative public Python API.

Both methods:

1. parse and validate the settings object before the plan lock;
2. reject a non-object root, duplicate keys, non-finite/out-of-range numbers,
   or depth greater than 32;
3. parse only the canonical UTC deadline format;
4. create a fresh `calc_flow::CancellationToken`;
5. construct the unchanged Rust `ExecutionOptions`;
6. enter the existing plan execution path.

Malformed direct native transport is redacted as:

```text
invalid execution settings transport
invalid execution deadline transport
```

It must not include the JSON document, offset, timestamp, parser source, byte
position derived from secret content, or a chained raw exception.

### 8.2 Native provider registration

The pure-Python wrapper chooses callback arity by passing or omitting a private
factory:

```python
type _ExecutionOptionsFactory = Callable[[str, str | None], object]


class Runtime:
    def register_provider(
        self,
        provider: str,
        name: str,
        version: str,
        callback: object,
        *,
        execution_options_factory: _ExecutionOptionsFactory | None = None,
    ) -> None: ...
```

This is the `_native.pyi` shape only. The public wrapper never exposes
`execution_options_factory`.

- public `accepts_execution_options=False` omits the factory;
- public `accepts_execution_options=True` passes the package-private factory
  from `calc_flow.execution`;
- the native factory validates that a supplied object is callable;
- the native provider factory retains the callback and factory as GC-traversed
  Python roots;
- the factory's presence, not signature inspection, fixes callback arity.

At operator invocation the bridge:

1. serializes `context.run.settings()` to canonical JSON;
2. formats `context.run.deadline()` with Rust
   `SecondsFormat::Micros` and `use_z=true`;
3. calls the cached package-private factory with those two data-only values;
4. calls the provider with two or three positional arguments as frozen above.

The private Python factory constructs an exact `ExecutionOptions` without
retaining the transport strings as mutable aliases. It validates its private
invariants and never imports modules dynamically during operator execution.

A private factory invariant failure becomes a fixed provider error:

```text
execution options bridge failed
```

The bridge does not append the execution-options repr, settings JSON, deadline,
factory exception, input batch, callback source, or callback repr.

The existing text of an exception deliberately raised by application callback
code remains governed by the existing non-Studio `ProviderError` contract.
5.2 guarantees only that the new bridge does not automatically add settings
or deadline data to it.

## 9. Studio Worker Private Projection

### 9.1 Parent registration record

A successful public single-array registration stores:

```python
{
    "kind": "provider",
    "provider": provider,
    "name": name,
    "version": version,
    "callback": callback,
    "options_schema": options_schema,
    "accepts_execution_options": accepts_execution_options,
}
```

The value is always an exact bool for new public registration records.

A mapped registration continues to store `provider_mode="mapping"` and does
not store `accepts_execution_options`.

The defensive registration snapshot copies this bool as data. Capability
assembly ignores it.

### 9.2 Worker reconstruction

After deserialization and before calling a registration method, the worker
uses this closed rule:

| Registration mode          | Field state           | Result                                      |
| -------------------------- | --------------------- | ------------------------------------------- |
| public single-array        | missing               | legacy compatibility; use `False`           |
| public single-array        | exact `False`         | restore two-argument callback               |
| public single-array        | exact `True`          | restore three-argument callback             |
| public single-array        | any other value       | fail closed                                 |
| mapped                     | missing               | restore current mapped callback             |
| mapped                     | exact `False`         | accepted only for old/private fixture parity |
| mapped                     | exact `True` or other  | fail closed                                 |

The fixed reconstruction error is:

```text
worker received an invalid execution-options registration contract
```

It includes no value, type name, registration identity, callback, source,
module path, cloudpickle detail, or chained raw exception.

For a valid public record, `_restore_registrations()` passes
`accepts_execution_options` to the public Python wrapper. It never passes the
private native factory from the parent; the worker wrapper supplies its own
trusted package-local factory.

### 9.3 Security and capability boundary

The flag:

- exists only in the trusted in-process registration record and selected
  parent-to-worker payload;
- cannot come from project JSON, a REST request, capability response, source
  bundle, import path, or arbitrary installed package;
- does not alter `serialized`, `lazyBuiltin`, or `unavailable`;
- does not make an unavailable callback serializable;
- does not make lazy `table_matmul@1` exist;
- does not alter the worker's exact-reference selection;
- does not expose callback, source, path, settings, deadline, or secret data
  through `/api/v2/capabilities`.

The Studio worker still calls:

```python
plan.execute(batches)
```

Therefore a transported opted-in provider receives
`ExecutionOptions(settings=None, deadline=None)` semantics: empty settings and
no deadline. Studio timeout, CPU, memory, input, row, and output limits remain
separate process/preview controls.

| Existing or new caller                                      | 5.2 behavior                                                        |
| ----------------------------------------------------------- | ------------------------------------------------------------------- |
| `plan.execute(inputs)`                                      | unchanged result/error/cancellation behavior                        |

- future `ExecutionOptions` fields may be added only as keyword-only fields

## 14. Rejected Alternatives

### 14.1 Only pass options to Rust

Rejected because Python providers would still not observe the run settings or
deadline, failing the stated cross-language goal.

### 14.2 Unconditionally call all providers with three arguments

Rejected as a source break for every existing callback.

### 14.3 Signature inspection or call-and-retry

Rejected because decorated callables, built-ins, variadic callables, callable
objects, and callback-internal `TypeError` make inference ambiguous and
potentially execute a callback twice.

### 14.4 `contextvars` or thread-local execution context

Rejected because execution crosses Rust/Tokio/Python boundaries, creates
implicit global state, complicates cancellation, and cannot express the
registration compatibility decision.

### 14.5 Native public `ExecutionOptions` pyclass

Rejected because the requested public value is ordinary immutable Python data;
a native class would complicate copying, typing, construction errors, and
wheel-independent documentation without adding engine capability.

### 14.6 Float Unix timestamp

Rejected because binary floating point can lose microseconds, timestamp
support varies at Python year boundaries, and local conversion mistakes become
harder to detect.

### 14.7 Integer epoch microseconds

Technically precise, but rejected for this bridge because negative/far-future
range conversion is less self-describing and more platform-sensitive than the
fixed UTC RFC 3339 representation.

### 14.8 Put the opt-in in capability schema v1

Rejected because callback arity is a trusted runtime implementation contract,
not project-editing metadata or proof of worker executability. Adding it would
break the closed v1 decoder and generated clients.

### 14.9 Extend mapped providers in 5.2

Rejected because `_register_mapping_provider` is private, built-ins already
have a stable two-argument contract, and no approved use case requires
run-context access there. A future public mapped-provider API needs its own
contract.

### 14.10 Map Studio preview limits into engine settings/deadline

Rejected because process CPU/memory/output/timeout limits and cooperative
engine execution context are different trust and lifecycle boundaries.

## 15. Critic Review Checklist

The critic should treat these as the highest-risk points:

1. whether exact-type option acceptance and redacted wildcard paths balance
   Python usability with the stated no-secret-in-errors contract;
2. whether canonical UTC text covers Python year 0001/9999 in the chosen
   `chrono` parser without platform timestamp APIs;
3. whether the package-private factory is retained and traversed without
   introducing a callback/runtime GC cycle;
4. whether async cancellation while the plan waits for its lock still leaves
   exactly one recoverable lifecycle path;
5. whether the post-callback cancellation check intentionally preserves
   cancellation-over-callback-error precedence;
6. whether any mapping provider can accidentally acquire a true opt-in through
   worker reconstruction;

   registration revision, compound helper partial success, or cloudpickle
   availability;
9. whether the implementation avoids broad strict-JSON helper refactors that
   change existing project/checkpoint error messages;
10. whether no size limit for settings is acceptable for this local,
    non-Studio public API, given that depth is bounded but bytes are not.
