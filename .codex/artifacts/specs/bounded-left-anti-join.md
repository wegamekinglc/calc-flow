# Bounded left anti join

A bounded left anti join returns each left input identity that has no right row with equal, non-null keys and a representable event time in the inclusive interval from `left_time - before` to `left_time + after`. The result contains the complete declared left schema. Duplicate left payloads retain their separate identities. Use the same finite and stream operator through Rust, project-v3, the Python expression and the advanced Python builder.

## Admission and output

- Existing source, schema, progress and whole-message checks run before join processing. They can reject an input before the operator sees any of its rows. A conversion error for a non-null timestamp fails the whole left or right input even if its key is null. A late representable left time strictly below its own watermark is dropped, including when its key is null.
- A nullable left row that reaches the join with a null event time can never match and is emitted immediately. A left null key with an on-time representable time is also immediately unmatched. Dropped right nulls and late right rows cannot serve as witnesses. Nulls produced on the left in these two cases count as emitted rows.
- For an on-time left row with valid keys and time, first probe retained rights, including after right EOF. A found witness suppresses that left identity permanently. In the absence of a witness, emit immediately when the right side has ended or its watermark is strictly beyond the inclusive upper bound. Otherwise retain the identity until the right side closes its interval. A right data message can mark many retained left identities without emitting them. Idle alone cannot prove absence.
- Immediate outputs from one left data message follow physical input order. A right progress transition releases closed, unwitnessed left rows in `(event_time, row_id)` order before forwarding its new output watermark or EOF. No global ordering across messages is promised. Finite execution applies the same operator after consuming both finite inputs. Direct operator termination closes both sides, with both state cuts committed together after the final output succeeds.
- Apply the existing whole-data-input match cap to emitted left identities. Each output envelope also respects the edge's row and byte limits. A watermark or EOF can finalize more rows than the data limit. Preflight the complete release before emitting a prefix and committing state or counters. Release reads the existing expiration index in bounded chunks. Keep at most one chunk of selection and output data plus the normal per-retained-run and per-group eviction bookkeeping. Check cancellation at bounded intervals even if every examined row already has a witness.
- On a returned emission failure the previous state, progress and output frontier can retry; a delivery prefix already accepted by a sink follows its delivery contract. A dropped handler future requires recovery. Persist and validate marks with their actual physical owner in native checkpoints. Recover before and after a mark and a progress release, and compare the delivered suffix with an uninterrupted job.

## Reference and checks

RisingWave tracks match degrees to implement anti joins on changing inputs. Calc Flow's append-only interval join needs a single persistent witness bit and finalizes an absence when watermarks or EOF close the interval. [RisingWave streaming hash join](https://github.com/risingwavelabs/risingwave/blob/bc563ec0330a6db01788959d249aee2126061d0d/src/stream/src/executor/hash_join.rs#L1138-L1178)

Verify the native Rust finite/stream APIs and managed V4 restore independently from the Python public collector and iterator. Cover nulls on both sides, conversion-error and late precedence, equal bounds and watermarks, right EOF followed by new left data, whole-batch rejection, two or more output envelopes, failed emission and cancellation. Use operation counts and a bounded workspace control for this new behavior.

The native control fixture retains 8,193 duplicate left rows in three morsels under one key. Right EOF releases all rows through a dropping collector with a 32-row, 4,096-byte edge budget. The oracle checks 257 consecutive output sequences and a maximum of 32 rows per envelope. On Linux x86-64, the thread-local heap counter measured 3,576 additional live bytes during the entire callback in the initial implementation. After integration onto main at `1239b1d9`, the same fixture and full output oracle measured 3,928 bytes on source `815d58d9`. The check allows 64 KiB across supported platforms. Existing retained state and collector-owned history are outside this figure. A companion fixture gives every left row a right witness, cancels the closure on the same executor thread, and checks that state remains available for retry. The successful retry reads each expired identity once, 8,193 eligibility reads compared with 16,386 in the initial two-pass implementation.

A separate native control sends one right event to mark those same 8,193 left identities, followed by a right message containing 4,096 identical events. The second message produced zero rows in both implementations. On the initial implementation it made 33,558,528 actual eligibility reads. Remembering the last fully marked window within the message reduced this to 8,193 reads. The witness scan still checks cancellation at each 4,096-row boundary and uses no heap storage for an already-marked window.
