# DAL-417 第一阶段：有限 SQL 准备复用

产品基线固定 `d9e2759fb31bfd0c915d31f0cc534665ece72ee9`，候选使用本任务专用分支。
旧 `a0708fcf` wheel 的产品源码已与基线不同，不作为本轮基线；复用其构建缓存，重新构建
匹配基线的 release wheel。基线和候选构建分别预估 10–15 分钟，构建单列，不计采集预算。
与 DAL-475 的 checkout、产物和绑定改造分离；正式采集前确认无任务构建争用。

先用基线现有 DataFusion 分阶段指标及同步/异步调用对照定位重复规划、运行时/会话准备、
执行和桥接成本。跨层时钟余项不能独占归因于线程投递或 GIL。仅在证据支持时，复用现有
受限行局部查询模板机制；配置、UDF 快照和图在计划边界固定，查询/别名/精确 schema
匹配。每次运行仍独立拥有输入、DataFusion 会话/内存池、执行树、指标与取消。

性能范围仅复用既有 32,768 行过滤/投影：整表 1×32,768，固定小批 64×512。
两场景分别覆盖调用固定成本与批次放大效应；不采样 Arroyo、streaming 或窗口。
沿用 sql-arrow-comparison 的 Arrow fixture、逐值/列/顺序 oracle、file IPC 完整消费边界
和进程清理。新 worker 支持基线/候选 seal。独立诊断记录逐次 DataFusion 指标，
诊断 API 时钟包含指标 getter，余项不得当成纯线程投递；正式采样复用原 API 调用与
全部绑定/执行/包装 span，在输出 IPC 后读取最后一次指标。
最后一次查询的 DataFusion 阶段明确标记，不将它冒充整段或乘以批次数。
准备、首次执行/暖身、执行到 Arrow、结果包装及输出 IPC 分列；不隐藏冷准备成本。

固定两轮，每轮每场景十对相邻 AB/BA（偶数组基线先，奇数组候选先），共 80 次正式观测。
预检固定为每场景每 side 一次，共四次；基线/候选诊断各有整表、小批的同步/异步四序列。
每轮使用新进程；双方同样暖身一次，暖身和诊断不进入正式统计，保留原始记录。
遵循仓库成对耗时变化的精确中位数置信区间和 +5% 两轮规则，不补样选结果。
主要指标为已备输入放行到父进程完整 Arrow Table 可消费的延迟、绝对输入吞吐；
另列 API 结果就绪及准备/执行阶段。输入批形状不变，数据面始终 Arrow/Batch/IPC。

本轮累计采集硬预算 600 秒，覆盖 fixture、预检、诊断、暖身、失败、正式进程和清理。
构建完成后启动持久预算账本，任何采集先扣已用时间并保留退出清理余量；单调用 30 秒。
资源 worker CPU 4–7、controller CPU 0–1、Tokio 4 workers、其他线程 1；无锁频/独占保证。
若环境或预算不足，保留现有证据并如实报告，不扩大场景或重试直到得到收益。

必要回归覆盖相同计划重复/不同输入、输入不变、并发及取消后的独立执行，精确 schema、
配置、图和 UDF snapshot 隔离，以及不适合复用的查询继续走原有规划。全量与覆盖率交 CI。
